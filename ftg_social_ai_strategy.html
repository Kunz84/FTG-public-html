02 — The Correct Workflow

Content Creation → UTM → Publish → Log

UTM parameters are generated by Abacus before posting — embedded in copy before Blotato publishes. This is not retroactive. The flow is strictly left-to-right.

1

Content Brief

You brief the Abacus agent. Campaign name, platform targets, asset location (GDrive or Airtable).

2

Claude Writes Copy

Abacus calls Claude model. Hook, body, CTA. Analyses Airtable historical top performers first.

3

UTM Generated

Agent auto-builds UTM URL from campaign slug, platform name, post ID. Embeds in copy CTA.

4

Media Pulled

Video or image fetched from Google Drive or Airtable attachment. Uploaded to Blotato via presigned URL.

5

Blotato Publishes

blotato_create_post called per platform. Post scheduled or published immediately. Blotato handles timing.

6

Airtable Logged

Full record written: copy, image URL, UTM fields, platform, scheduled time, Blotato post ID.

UTM Parameter Convention

// ABACUS generates these programmatically — no manual work

utm_source = instagram // platform name, auto-detected from target
utm_medium = social // always "social"
utm_campaign= q4-launch // from your campaign brief
utm_content = post-047 // auto-incremented from Airtable Post ID

// FINAL URL embedded in post copy before publishing:
https://ftgai.com/launch?utm_source=instagram&utm_medium=social&utm_campaign=q4-launch&utm_content=post-047

05 — Skills vs Data

What Lives Where

Skill.md files in Abacus teach the agent HOW to act. Airtable stores WHAT actually happened. Never mix them.

Abacus Agent Console

Skill.md Files

Instructions / Procedures / Capabilities — rarely change
  • blotato-publishing.md — How to publish posts via Blotato MCP, presigned upload flow, scheduling
  • utm-generation.md — Naming convention, how to auto-increment Post ID from Airtable, URL construction
  • content-analysis.md — How to query top performers, extract patterns, generate informed copy
  • airtable-sync.md — Table structure, field names, how to read/write Posts and Campaigns tables
  • gdrive-media.md — How to locate, download, and upload video/image from Google Drive to Blotato
  • campaign-brief.md — How to accept a campaign brief and orchestrate the full creation → publish → log flow
Airtable

Operational Data

Records / History / Metrics — updated constantly
  • Posts table — Every post ever created, copy, media, UTM params, platform, scheduled time
  • Campaigns table — Campaign name, slug, start/end date, target platforms, base URL
  • Analytics table — Views, likes, comments, reach per post, updated 48hrs post-publish
  • Media Library — Google Drive file IDs, descriptions, which posts used each asset
  • System Log — What ran when, success/failure, automation execution history
  • Performance Trends — Rollup of top hooks, formats, CTAs for Claude to reference
Key principle: Skill files are the agent's memory of how to work. Airtable is the record of what it did. Airtable is also what makes your HTML dashboard possible — it reads from there to show you everything at a glance.

10 — Quick Start Checklist

Get Running in Week 1

6 steps to your first UTM-tracked, analytics-logged, multi-platform post.

  • 1
    Create Airtable Base 4 tables: Posts, Campaigns, Media Library, System Log. Use schema above. Set Full UTM URL and Engagement Rate as formula fields.
  • 2
    Connect Blotato MCP to Abacus In Abacus Agent Console → MCP settings → Add remote server: https://mcp.blotato.com/mcp — Transport: SSE — Auth header: blotato-api-key: [your key]
  • 3
    Connect Google Drive & Airtable In Abacus → Connectors → Google Drive (OAuth) + Airtable (API token). Test: read a Drive file and an Airtable record.
  • 4
    Write Your Skill.md Files Start with utm-generation.md, blotato-publishing.md, and airtable-sync.md. These teach the agent your exact conventions.
  • 5
    Run First End-to-End Post Brief the agent: campaign name, base URL, target platform, GDrive video or image. Verify UTM URL in Airtable, post appears in Blotato queue, GA receives traffic.
  • 6
    Install n8n Analytics Workflow 48hr scheduled workflow: fetch Blotato analytics for published posts → update Airtable views/likes/comments/reach fields → log run to System Log table.
11 — Tool Stack Roles

Each Tool, One Job

🤖

Abacus AI

Orchestrator. Schedules daemons, calls Claude for copy, coordinates Airtable reads/writes, triggers Blotato via MCP. The engine that runs it all autonomously.

🧠

Claude (via Abacus)

Content brain. Specified as the model for copy generation tasks. Produces hooks, body copy, CTAs informed by top-performer data from Airtable.

📡

Blotato

Publishing layer. 36 MCP tools, 9 platforms, 8-platform analytics. Handles OAuth tokens per platform. Posts go out on time even if agent isn't running.

📊

Airtable

Single source of truth. Every post, UTM param, metric, and log lives here. What the dashboard reads. What Claude learns from. Historical reference.

☁️

Google Drive

Media library. Master videos and images. Agent pulls via Drive connector, uploads to Blotato. Organised by campaign slug and platform.

⚡

n8n

Automation bridge. Scheduled analytics pulls from Blotato → Airtable updates. Execution logs. Community Blotato node available natively.

📈

Google Analytics

Conversion tracking. UTM parameters bridge social posts to website behaviour. Tracks traffic, conversions, and ROI per campaign and platform.

🔥

Microsoft Clarity

Page intelligence. Heatmaps, session recordings, and drop-off analysis for visitors arriving via UTM-tagged posts. Informs landing page improvements.

🖥️

HTML Dashboard

Visibility layer. Single-pane control panel hosted on GitHub Pages. Reads Airtable and Blotato APIs. System status, recent posts, top performers — one URL.
