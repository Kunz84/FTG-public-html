07 — The Autonomous Loop

Don't Script the Loop. Use a Self-Improving Task.

This is the single biggest correction to the old architecture. You do not need n8n + cron + a hand-written "analyse top performers" prompt to close the feedback loop. Abacus Self-Improving Tasks are that loop as a first-class product feature — with the one safeguard hand-built loops always lack: an independent evaluator so the agent can't grade its own homework.

❌ The old hand-built loop

  • n8n cron pulls Blotato analytics on a timer
  • Writes metrics back to Airtable
  • A prompt asks Claude to "look at top posts and do better"
  • No baseline, no evaluator — the model marks its own work
  • You maintain the workflow, the schedule, and the glue

✅ The native Self-Improving Task

  • Objective — e.g. grow engagement rate per post
  • Metric — one measurable number, tracked run over run
  • Baseline — measured before any change
  • Each run — reviews history → ONE focused change → applies it → independent evaluator grades improved / unchanged / regressed
  • Regressions trigger recovery; plateaus auto-pause to save credits; progress dashboard is built in

10 — Abacus vs "Claude-Only"

The old plan asked "should we build this on Abacus or on Claude?" That's a false choice. Abacus is the operating system; Claude is one of the models it runs. Via RouteLLM you get Claude Opus 5 plus GPT-6 and Gemini, inside a platform that also gives you scheduling, hosting, Studio, and the self-improving loop.

What Runs Where — Abacus Is the OS, Not One Tool

The biggest reframe: Abacus is not a peer in this list — it is the operating system the rest plug into. External tools now play focused, optional roles.

🧠

FTG Agent Console (Abacus AI OS)

The whole platform. Agents, RouteLLM model access, Studio, Self-Improving Tasks, daemons, Swarms, Personal Agents, SuperComputer hosting, connectors. It runs, hosts, and improves the system — not just orchestrates it.

🎯

RouteLLM (inside Abacus)

Model layer. Routes each task to Claude, GPT, Gemini, or others by quality and cost. "Abacus vs Claude" is a false choice — Claude runs inside Abacus.

🎬

Studio (inside Abacus)

Creative engine. 50+ image/video/audio models, avatars, and an editor. Generates the actual media — not just storage.

🔁

Self-Improving Task (inside Abacus)

The autonomous loop. Native scheduled task with an independent evaluator and metric tracking. Replaces the hand-built n8n + cron loop entirely.

🖥️

SuperComputer (inside Abacus)

Always-on host. Persistent cloud machine — root, Docker, Postgres — that runs the loop and hosts the dashboard app 24/7.

📡

Blotato

Publishing layer. Connected via MCP. 9 platforms, per-platform OAuth, 8-platform analytics. Posts go out on schedule.

📊

Airtable / Postgres

Data layer. Airtable (via MCP) to start; Postgres on SuperComputer to scale. Every post, UTM, metric, and log lives here.

☁️

Google Drive + GA4

Native connectors. Drive stores master media; GA4 closes the funnel from UTM click to conversion. First-party, no MCP.

⚙️

n8n (optional)

Edge-case bridge only. Keep it for a niche third-party webhook Abacus can't yet reach. It is no longer the loop or the scheduler.
